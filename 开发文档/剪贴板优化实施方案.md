# 剪贴板优化实施方案

> 创建日期：2026-05-08
> 状态：**已实施**（v1.5）

## 1. 背景与问题

### 1.1 当前实现

粘贴卡数据存储在 SQLite 本地数据库中（`clipboard_items` 表），文本内容以原文存储，图片以完整 Base64 字符串存储。每次启动和剪贴板变化时全量加载所有记录到内存。

### 1.2 风险

| 风险 | 说明 |
|------|------|
| 数据库膨胀 | 图片 Base64 比原图大约 33%，大量截图后 DB 文件可达 GB 级 |
| 内存占用 | 无分页机制，全量加载到内存 |
| 启动变慢 | 数据量越大加载越慢 |
| 备份困难 | 大体积 .db 文件导出导入耗时 |

---

## 2. 方案概述

本次优化包含三个子方案：

1. **图片文件化存储** — 图片改为存文件系统，DB 只存文件路径和缩略图
2. **虚拟滚动加载** — 列表仅渲染可视区域 DOM 节点
3. **自动过期清理** — 新增过期机制，定期清理旧数据

---

## 3. 图片文件化存储

### 3.1 核心思路

粘贴图片时，将完整图片保存为 PNG 文件到 AppData 目录下的图片文件夹，数据库只保留：
- `image_path` — 原图文件路径（用于复制到系统剪贴板时读取）
- `thumbnail_base64` — 小尺寸缩略图的 Base64（用于列表展示）

### 3.2 文件存储路径

```
%APPDATA%/com.mmy-tools.todolist/clipboard_images/{uuid}.png
```

### 3.3 变更清单

#### 3.3.1 数据库变更

`clipboard_items` 表新增两列：
```sql
ALTER TABLE clipboard_items ADD COLUMN image_path TEXT;
ALTER TABLE clipboard_items ADD COLUMN thumbnail_base64 TEXT;
```

- `image_path` 存相对路径或绝对路径（优先相对路径，便于迁移）
- `thumbnail_base64` 存压缩后的缩略图 Base64（最大宽度 300px，用于卡片预览）

#### 3.3.2 Rust 后端（`database.rs`）

- `ClipboardItem` 模型新增 `image_path` 和 `thumbnail_base64` 字段
- `add_clipboard_item` / `update_clipboard_item` SQL 参数增加新字段
- `get_clipboard_items` SELECT 语句包含新字段
- 新增 `save_clipboard_image()` 方法：接收 base64，生成缩略图，保存原图到文件系统，返回路径+缩略图
- 新增 `get_clipboard_image_bytes()` 方法：根据路径读取原图字节，用于写入剪贴板
- `delete_clipboard_item` 删除时同步删除对应图片文件
- `init()` 中添加列迁移逻辑（`ALTER TABLE ... ADD COLUMN`，忽略已存在错误）

#### 3.3.3 Rust 命令（`commands.rs`）

- 修改 `add_clipboard_item`：如果传入的是图片（`image_base64` 非空），先调用 `save_clipboard_image()` 存文件，再存 DB
- 新增命令 `read_clipboard_image_file`：根据路径读取原图返回 base64（用于复制到系统剪贴板）
- `NewClipboardItem` 结构新增 `imagePath` 和 `thumbnailBase64` 字段

#### 3.3.4 前端类型（`types/index.ts`）

```ts
export interface ClipboardItem {
  // ...现有字段
  imagePath?: string;      // 新增：原图文件路径
  thumbnailBase64?: string; // 新增：缩略图 base64
}
```

#### 3.3.5 前端 Store（`clipboardStore.ts`）

- `pasteFromClipboard()` 中的图片粘贴逻辑：不再存完整 base64，改为通过新命令存文件
- 去重检查需适配新的存储方式

#### 3.3.6 前端组件（`ClipboardItemCard.vue`）

- 图片显示改为使用 `item.thumbnailBase64`（如果存在则用缩略图，否则回退到 `item.imageBase64` 兼容旧数据）
- 复制图片时：先尝试调用 `read_clipboard_image_file` 读取原图，再写入系统剪贴板

#### 3.3.7 旧数据迁移

不主动迁移旧数据。旧数据 `imageBase64` 字段继续有效，新数据使用 `imagePath` + `thumbnailBase64`。前端兼容两种格式。

## 4. 虚拟滚动

### 4.1 方案选择

使用 `@tanstack/vue-virtual` 库实现虚拟滚动。相比分页：
- 用户体验更连贯（无需"加载更多"按钮）
- 对现有拖拽功能影响小（`vuedraggable` 可与虚拟滚动配合）
- 实现成本适中

### 4.2 变更清单

#### 4.2.1 依赖

```bash
npm install @tanstack/vue-virtual
```

#### 4.2.2 `ClipboardPanel.vue`

- 移除 `vuedraggable` 的 `draggable` 全量渲染，改用 `useVirtualizer` 创建虚拟列表
- 容器设置固定高度 + `overflow-y: auto`
- 计算每个卡片固定高度（或使用动态高度估计）
- 只渲染可视区域 + buffer 区域的卡片

#### 4.2.3 `ClipboardItemCard.vue`

- 确保卡片高度一致或通过虚拟滚动的 `estimateSize` + `measureElement` 支持动态高度

> **注意**：拖拽排序与虚拟滚动的兼容性需要特别处理。如果 `vuedraggable` 与虚拟滚动不兼容，考虑降级为分页加载（每次加载 50 条，滚动到底部加载更多）。

## 5. 自动过期清理

### 5.1 过期策略

| 分类 | 默认过期时间 | 说明 |
|------|-------------|------|
| 文本（builtin_text） | 30 天 | 日常复制文本时效性短 |
| 图像（builtin_image） | 7 天 | 图片占空间大，短时效 |
| 自定义分类 | 永不过期 | 用户创建的分类不自动清理 |

### 5.2 变更清单

#### 5.2.1 数据库变更

```sql
ALTER TABLE clipboard_items ADD COLUMN expires_at INTEGER;
-- NULL 表示永不过期
```

#### 5.2.2 Rust 后端

- `ClipboardItem` 模型新增 `expires_at` 字段（`Option<i64>`）
- `add_auto_clipboard_text()` / `add_auto_clipboard_image()` 根据分类自动计算过期时间
- `add_clipboard_item()` 支持传入 `expires_at`
- `Database::init()` 末尾新增过期清理：`DELETE FROM clipboard_items WHERE expires_at IS NOT NULL AND expires_at < ?`
- `get_clipboard_items()` 自动过滤掉已过期但未清理的记录
- `delete_clipboard_item()` 删除时同步清理图片文件（如果 `image_path` 非空）

#### 5.2.3 前端类型

```ts
export interface ClipboardItem {
  // ...现有字段
  expiresAt?: number | null;  // 新增
}
```

#### 5.2.4 前端组件

**右键菜单新增「设置过期时间」：**
- 选项：1小时 / 1天 / 7天 / 30天 / 永不过期
- 仅对文本和内置图像分类可用
- 自定义分类不显示此选项

#### 5.2.5 手动清理入口

在剪贴板面板的空白区域右键，新增「清理已过期项目」菜单项，手动触发立即清理。

## 6. 实施顺序

按以下顺序分步实施，每步完成后可独立验证：

### 第一阶段：过期清理（改动最小，价值明确）
1. 数据库迁移：新增 `expires_at` 列
2. 后端模型、数据库方法、命令更新
3. 自动计算过期时间（添加时）
4. 启动时过期清理
5. 前端右键菜单设置过期时间
6. 前端过期提示 UI

### 第二阶段：图片文件化存储（改动最大，收益最高）
1. 创建图片存储目录
2. 后端图片保存/读取方法
3. 数据库迁移：新增 `image_path`、`thumbnail_base64` 列
4. 命令层适配
5. 前端类型和 Store 更新
6. 前端组件显示缩略图
7. 删除时同步清理图片文件

### 第三阶段：虚拟滚动 / 分页加载（体验优化）
1. 安装 `@tanstack/vue-virtual`
2. 验证与 `vuedraggable` 兼容性
3. 实现虚拟滚动或降级为分页加载

---

## 7. 风险与回退

| 风险 | 应对 |
|------|------|
| 旧数据 imageBase64 兼容 | 前端同时支持 imageBase64 和 imagePath 两种格式 |
| 虚拟滚动与拖拽不兼容 | 降级为分页加载（滚动到底部加载更多） |
| 图片文件丢失 | 前端检测到文件不存在时显示"图片已丢失"占位 |
| 数据库迁移失败 | ALTER TABLE 使用 IF NOT EXISTS 模式，已存在列不报错 |
