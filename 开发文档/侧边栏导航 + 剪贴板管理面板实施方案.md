# 侧边栏导航 + 剪贴板管理面板实施方案

## 背景

当前 TodoList 应用为单面板布局（宽度400px），用户希望添加类似 Mac 微信风格的左侧图标导航栏，在"任务卡"和"剪贴板管理"两个面板间切换。窗口宽度需增加，剪贴板使用独立的分类体系。

---

## 方案概述

1. **左侧边栏（~60px）**：纯图标导航按钮，垂直排列
   - 📋 任务面板
   -  剪贴板面板
   - （底部）⚙️ 设置按钮
2. **主内容区**：保留现有 header + 列表 + footer 布局，通过 `v-show` 切换面板
3. **剪贴板数据**：新建 `clipboard_categories` 和 `clipboard_items` 两张 SQLite 表，与任务数据完全隔离
4. **窗口宽度**：从 400px 调整到 680px

---

## 实施步骤（13步，按依赖顺序）

### Phase 1: Rust 后端（数据层）

**步骤 1** — `desktop/src-tauri/src/models.rs`：新增 `ClipboardCategory` 和 `ClipboardItem` 结构体
- 字段比 Task 更精简：无 status/dueDate/startDate/isPinned/updatedAt/description/thumbnailBase64
- 保留：id, categoryId, title, content, imageBase64?, priority, sortOrder, createdAt

**步骤 2** — `desktop/src-tauri/src/database.rs`：新建表和 CRUD
- `CREATE TABLE IF NOT EXISTS clipboard_categories`（id, name, color, sort_order, created_at）
- `CREATE TABLE IF NOT EXISTS clipboard_items`（id, category_id, title, content, image_base64, priority, sort_order, created_at）
- 初始化默认剪贴板分类（类似任务的 ensure_default_category）
- 新增 10 个 CRUD 方法（get/add/update/delete/reorder × 2）

**步骤 3** — `desktop/src-tauri/src/commands.rs`：新增 10 个 Tauri 命令
- 每个命令薄包装调用对应的 db 方法，遵循现有命名规范

**步骤 4** — `desktop/src-tauri/src/lib.rs`：在 `invoke_handler` 中注册 10 个新命令

### Phase 2: TypeScript 前端（类型和工具层）

**步骤 5** — `desktop/src/types/index.ts`：新增 `ClipboardCategory` 和 `ClipboardItem` 接口

**步骤 6** — `desktop/src/utils/db.ts`：新增剪贴板 invoke 函数
- 10 个函数对应后端命令，模式复用现有 category/task 函数

**步骤 7** — `desktop/src/stores/clipboardStore.ts`（新建）：Pinia store
- 结构参考 `categoryStore` + `taskStore` 的合并
- 包含：categories, items, selectedCategoryId, loading
- 方法：分类 CRUD、项目 CRUD、pasteFromClipboard（读取剪贴板并创建条目）

### Phase 3: 窗口配置

**步骤 8** — `desktop/src-tauri/tauri.conf.json`：
- `"width": 400` → `680`
- `"minWidth": 300` → `500`

### Phase 4: UI 重构

**步骤 9** — `desktop/src/views/Home.vue`：核心改造
- 外层加 `app-layout` flex 容器（横向）
- 左侧加 `<nav class="sidebar">`（60px 固定宽，图标按钮）
- 右侧 `main-content` 内含 `v-show` 切换的任务面板和剪贴板面板
- 新增 `activePanel` ref 和 `switchPanel()` 函数
- 更新 `COMPACT_WIDTH` 从 320 → 400（考虑侧边栏存在后的总宽）
- 添加窗口宽度迁移逻辑（旧用户 windowWidth < 500 时重置为 680）
- 拖拽区域处理：sidebar 设为 drag region，内部按钮 no-drag

**步骤 10** — `desktop/src/components/ClipboardPanel.vue`（新建）：剪贴板面板
- 分类标签栏（复用 CategoryTabs 模式，数据来自 clipboardStore）
- 搜索栏
- 剪贴板项目列表（可滚动）
- 底部"从剪贴板粘贴"按钮

**步骤 11** — `desktop/src/components/ClipboardItemCard.vue`（新建）：剪贴板项目卡片
- 简化版 TaskCard：显示标题、内容预览、缩略图（可选）、优先级星级、创建时间、删除按钮
- 右键菜单：编辑、删除、复制内容、复制图片
- 复用 TaskCard 的 CSS 类保持视觉一致

**步骤 12** — `desktop/src/components/SettingsPage.vue`：修复高度
- `height: 100vh` → `height: 100%`（使其填充 flex 父容器而非视口）

**步骤 13** — 测试与打磨
- 验证拖拽区域不冲突
- 浅色/深色主题下侧边栏颜色正确
- 窗口最小宽度限制生效
- 旧用户窗口尺寸自动迁移

## 风险与规避

| 风险 | 规避方案 |
|------|----------|
| 拖拽区域与按钮冲突 | sidebar 设 drag region，按钮设 no-drag（同现有 header 模式） |
| 窗口缩太小内容过窄 | minWidth 从 300 提到 500 |
| 旧用户窗口尺寸被覆盖 | 迁移逻辑：windowWidth < 500 时重置为 680 |
| 浅色主题下侧边栏颜色不协调 | 使用 `html.dark .sidebar` 选择器区分深浅主题 |
| SQLite 旧库缺新表 | `CREATE TABLE IF NOT EXISTS` 自动处理 |
| 精简模式（置顶）宽度不够 | COMPACT_WIDTH 从 320 调整到 400 |

## 验证方式

1. `npm run tauri dev` 启动开发模式
2. 验证侧边栏图标点击切换面板
3. 验证剪贴板面板：粘贴内容、创建分类、删除项目
4. 验证拖拽窗口（点击侧边栏空白处和主内容区 header）
5. 验证主题切换（浅/深）下侧边栏颜色正确
6. 验证窗口最小宽度限制
7. 构建测试：`npm run tauri build -- --bundles nsis`
