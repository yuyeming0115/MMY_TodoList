# 剪贴板图像跨应用拖拽方案

## 背景

当前剪贴板卡片支持文字拖拽到外部应用，但图像只能写入系统剪贴板后提示用户 Ctrl+V。

## 现状分析

- 文字拖拽：`dataTransfer.setData('text/plain', ...)` — 可直接拖到外部应用 ✓
- 图像拖拽：折中方案 — 写入系统剪贴板 + 提示 Ctrl+V ✗
- 代码位置：`desktop/src/components/ClipboardItemCard.vue` 第 276-303 行

**关键发现**：后端 `save_clipboard_image()` 已将每张图像保存为本地文件，`image_path` 也存入了数据库。问题只是**前端 store 没有读取这个字段**。

## 可行方案

### 方案 A：暴露 imagePath + 文件 URI 拖拽（推荐）

**原理**：`dataTransfer.setData('text/uri-list', 'file:///path')` 可让外部应用直接接收文件。

**改动范围**：2 个文件，约 10 行代码

**步骤 1** — `desktop/src/stores/clipboardStore.ts`

在 `ClipboardItem` 类型中加入 `imagePath` 字段，并在数据库查询结果映射中读取 `image_path`。

**步骤 2** — `desktop/src/components/ClipboardItemCard.vue` 第 284-298 行

```typescript
if (props.item.imagePath) {
  // 有本地路径：用文件 URI 实现真正拖拽
  const filePath = props.item.imagePath.replace(/\\/g, '/');
  e.dataTransfer.setData('text/uri-list', `file:///${filePath}`);
  e.dataTransfer.setData('text/plain', props.item.imagePath);
  e.dataTransfer.effectAllowed = 'copy';
} else if (props.item.imageBase64) {
  // 无本地路径：保持现有剪贴板方案
  const base64Data = props.item.imageBase64.replace(/^data:image\/\w+;base64,/, '');
  await invoke('write_image_to_clipboard', { base64: base64Data });
  message.info('图片已复制到剪贴板，请在目标窗口 Ctrl+V 粘贴');
}
```

**效果**：拖拽到文件管理器、Photoshop、Word 等应用可直接放置图像，无需 Ctrl+V。

---

### 方案 B：base64 写临时文件再拖拽

对没有 `imagePath` 的图像，在 Rust 端写入临时目录，返回路径后用文件 URI 拖拽。

**改动范围**：新增 1 个 Rust 命令 + 前端调用 + 临时文件清理逻辑

**缺点**：`dragend` 事件不可靠，临时文件清理时机难把握；复杂度明显高于方案 A。

---

### 方案 C：Windows 原生 IDataObject COM 接口

在 Rust 端实现 Windows COM `IDataObject`，支持 `CF_HDROP` 格式。

**缺点**：需要 unsafe Rust + COM 交互，实现极复杂，跨平台需分别实现。

---

## 方案对比

| 方案 | 效果 | 改动量 | 推荐 |
|------|------|--------|------|
| A：文件 URI | 真正拖拽，覆盖所有已保存图像 | 2 文件，~10 行 | ✓ |
| B：临时文件 | 真正拖拽，覆盖 base64-only 图像 | 新增 Rust 命令 + 清理 | 可选扩展 |
| C：COM IDataObject | 最原生 | unsafe Rust + COM | 不推荐 |

### 拖拽体验修复（v1.5，2026-05-09）

**问题**：`vuedraggable`（Sortable.js 封装）在拖拽手柄上调用 `preventDefault()`，阻断原生 `dragstart` 事件，导致跨应用拖拽失效。

**解决方案**：在拖拽手柄上用原生 `mousedown` 拦截（`capture: true`），调用 `stopImmediatePropagation()` 阻止 Sortable.js 的捕获逻辑。

```typescript
// ClipboardItemCard.vue
function blockSortableMousedown(e: Event) {
  e.stopImmediatePropagation();  // 阻止 Sortable.js 的捕获
}

onMounted(() => {
  dragHandleRef.value?.addEventListener('mousedown', blockSortableMousedown, true);
});
```

**效果**：拖拽手柄只触发原生拖拽流程，不受 vuedraggable 干扰，跨应用拖拽恢复正常。

## 验证方式

1. 有 `imagePath` 的图像卡片：拖拽到文件管理器/桌面，应直接放置图像文件
2. 仅有 base64 的图像卡片：拖拽时仍提示 Ctrl+V（方案 A）
3. 文字卡片拖拽不受影响
