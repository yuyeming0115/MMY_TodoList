# 截图缩略图读取问题排查与修复

## 问题描述

右键任务卡片 → "截图存为缩略图" 功能中，PixPin 截图完成后窗口重新获得焦点时，读取剪贴板失败：

```
读取剪贴板失败: The image or the text that was about the be transferred to/from the clipboard could not be converted to the appropriate format.
```

## 问题原因

原始实现使用 `arboard::Clipboard::get_image()` 读取剪贴板图片。经过排查发现 PixPin（以及 Win+Shift+S）在剪贴板中存放的数据格式与 arboard 预期不兼容：

| 格式ID | 名称            | 大小      | 说明                      |
|--------|-----------------|-----------|---------------------------|
| 49161  | DataObject      | 8 bytes   | OLE 数据对象              |
| 50062  | PixPinData      | 201 bytes | PixPin 自定义格式         |
| 8      | CF_DIB          | 761740 bytes | 设备无关位图（可用）   |
| 17     | CF_DIBV5        | 761812 bytes | DIB v5 格式（可用）    |
| 49171  | Ole Private Data| 264 bytes | OLE 私有数据              |

arboard 在 Windows 上的图片读取逻辑是：
1. 先尝试注册的 "PNG" 格式（PixPin 未提供）
2. 再尝试 `CF_DIBV5`（有数据，但 BmpDecoder 解码失败）
3. 返回 `Error::ConversionFailure`

问题出在 `image` crate 的 `BmpDecoder` 无法正确解码 PixPin 产出的 DIBV5 数据，导致 arboard 报 `ConversionFailure`。

## 解决方案

使用 `clipboard-win` 直接读取剪贴板中的位图数据，绕过 arboard 的限制。

### 修改的文件

| 文件 | 修改内容 |
|------|----------|
| `desktop/src-tauri/Cargo.toml` | 添加 `clipboard-win = "5"` 依赖 |
| `desktop/src-tauri/src/lib.rs` | 重写 `read_clipboard_image()` 函数 |
| `desktop/src/components/TaskCard.vue` | 前端先尝试 Tauri clipboard-manager 插件，回退到后端 |

### 读取策略

新的 `try_read_once()` 函数按以下优先级尝试：

1. **PNG 注册格式**：检查是否有注册的 "PNG" 格式，直接读取 PNG 字节流
2. **CF_DIBV5（格式 17）**：用 `clipboard_win::raw::get_vec()` 读取，再用 `BmpDecoder` 解码
3. **CF_DIB（格式 8）**：同样方式读取和解码

每种方法解码成功后，将图像数据编码为 PNG 并转为 base64 返回。

### 重试机制

外层循环最多重试 10 次，每次间隔 500ms，处理剪贴板数据尚未就绪或被占用的情况。

## 经验总结

- `arboard` 是高级封装库，对某些剪贴板格式（如 PixPin 的 DIB 数据）兼容性不够
- 底层 Windows API（通过 `clipboard-win`）可以直接读取原始字节，绕过解码问题
- 调试时先枚举剪贴板中所有可用格式，确认数据存在再排查解码环节
- 多级回退策略（PNG → DIBV5 → DIB）能覆盖不同截图工具的数据格式
